Issues found and fixed during verification (each now covered by a test):

- Wildcard CORS origins (`https://*.example.com`) passed validation because URL parsing accepts `*` in hostnames → now rejected explicitly.
- Disallowed CORS origins still received `Access-Control-Allow-Credentials` → CORS now runs only for allowlisted origins.
- The first readiness check after startup reported a healthy Redis as down (offline queue disabled) → `ping` now waits, bounded, for the connection.
- DB-unavailable errors from the Prisma 7 driver adapter surfaced as 500 → mapped to 503 based on the adapter's real error shape.
- Access logs carried no request id, and recorded the proxy's IP instead of the client's → fixed (`quietReqLogger`, `req.ip`).
- nginx redirects used the container's internal port (broke behind port mapping) → `absolute_redirect off`.
- Zod's JIT capability probe violated the admin CSP (`script-src eval`) → Zod jitless mode in the browser.
- **First GitHub CI run:** type-aware lint failed on the clean runner (100 errors) because the Prisma client and `@nexora/shared` types are generated artifacts that did not exist yet; locally they masked the problem. Reproduced by deleting the artifacts, then fixed with a root `codegen` step that `lint`, `typecheck` and `test` all run first.
- A 393 MB deploy footprint was investigated: `prisma` moved to devDependencies and migrations got a separate `migrator` image target (the residual size is R-07).

### Node.js compatibility (follow-up)

A user on Node 23.7.0 could not install the project. Investigation on a real Node 23.7.0 binary found:
`engine-strict=true` turned dependencies' declared engines (many tools exclude odd releases on principle)
into hard errors; Prisma's `preinstall` script is a Node-version gate that rejects 23.x; and jsdom 30
(test-only) needs `zlib.createZstdDecompress`, which Node 23.7 lacks. Fixes: engines are now warnings
(the project's own range is `^22.22.0 || >=23.6.0`, checked by `nexora doctor`), Prisma's gate script no
longer runs (its engines still install via `@prisma/engines`), and jsdom is pinned to 29.1.1. On Node
23.7.0: fresh install, lint, format, typecheck, build, all unit/integration tests, drift check, the E2E
suite and `nexora dev` pass. CI now also runs the test suite on Node 23.7.0 and 24.

- **CI on GitHub:** run #1 (commit `d2b4f86`) passed the test job (unit, integration, drift check, E2E on 3 viewports), the audit, and all image builds; the lint job failed as described above. Run #2 (commit `57d5e1b`, with the fix) passed **all four jobs** on GitHub.

- **Admin bundle:** about 167 kB gzipped across vendor chunks (React 68 kB, data/Zod+Query 34 kB, router 31 kB, other 26 kB, app 8 kB). Budget for the admin shell: ≤ 200 kB gzipped initial JS; route-level code splitting arrives with more routes.

## Milestone 2 — Identity, access control and audit

Plan, scope and decisions: [`docs/milestones/m2-identity-access.md`](../milestones/m2-identity-access.md).

### Starting point
M1 delivered the API kernel, the `system_state` table and an admin shell with one public status page. No
authentication existed and every endpoint was public.

### What was built
- **Data model** (migration `20261031120000_identity_access_audit`): `sites`, `users`, `user_credentials`,
  `sessions`, `roles`, `capabilities`, `role_capabilities`, `role_assignments`, `password_reset_tokens`,
  `audit_events` (append-only trigger), `rate_limit_buckets`; CHECK constraints for normalised emails, key
  formats and hash lengths; 10 core capabilities and 6 system roles seeded by the migration.
- **Setup wizard**: environment check → site → security → first super administrator. It needs the one-time
  setup token (printed at startup, or `SETUP_TOKEN`); installation is serialised with a PostgreSQL advisory
  lock and permanently locked afterwards.
- **Sessions**: Argon2id passwords; opaque 256-bit session tokens with only their SHA-256 stored; cookie
  `__Host-nexora_session` (Secure) or `nexora_session` (plain-HTTP development), HttpOnly, SameSite=Strict;
  idle and absolute expiry; rotation on sign-in and password change; revocation of one session, all other
  sessions, or all of a user's sessions.
- **CSRF**: `Origin`/`Sec-Fetch-Site` verification on every unsafe request, plus a session-bound HMAC token
  (`X-CSRF-Token`) on every cookie-authenticated mutation.
- **Rate limits** (Redis when configured, PostgreSQL otherwise): sign-in per address and per account,
  password reset requests and confirmations, setup. Responses carry 429 + `Retry-After`.
- **Authorisation**: a global guard that denies by default; every route is `@Public`, `@Authenticated` or
  `@RequireCapabilities(...)`, enforced by a route-inventory test. Escalation rules live in one service: no
  granting of unheld capabilities, no self role/status change, no editing of more privileged users or of
  one's own role, the Super Administrator role is immutable, and the last active super administrator cannot
  be demoted or suspended.
- **Users, roles, account, settings, audit APIs** (24 OpenAPI paths), password reset by email (development
  transports only, see limitations) and operator recovery: `nexora user reset-password --email <email>`.
- **Admin UI**: setup wizard, sign-in, forgot/reset password, users (search, filters, pagination, create,
  edit, role, suspend/reactivate, set password, sessions), roles (custom roles, capability editor), audit log
  (filters, pagination), profile (name, password, own sessions), site settings; capability-aware navigation
  and routes; session-expiry handling; lazy-loaded routes.

Issues found and fixed during M2 verification:

- **Sign-out did not leave the page**: clearing the whole query cache detached the session observers, so the
  route guards never re-rendered → only the session entry is replaced and private queries are removed
  (covered by the admin auth-flow tests and E2E).
- **Route-level code splitting broke the CSP guarantee**: chunks containing shared schemas were evaluated
  before the entry's Zod jitless switch, so Zod probed for `eval` and the CSP reported a violation. Rolldown's
  `strictExecutionOrder` fixed it but cost ~6 kB of runtime wrappers; instead `src/zod-config.ts` is placed in
  Zod's own chunk, which every schema chunk imports (the E2E CSP test guards this).
- **Mobile layout**: row actions in the users table were pushed off-screen and toasts covered the header →
  role and status move under the name below the `sm` breakpoint; toasts sit bottom-right.
- **nginx forwarded `Host` without the port** (`$host`), so behind a mapped port the CSRF origin check would
  reject every sign-in through the container stack → `$http_host`.
- **Own password change had no automated test** (found while mapping the acceptance criteria to evidence) →

- **`nexora user reset-password` always failed**: pnpm 10 forwards a literal `--` to the script, which made

- **Initial admin bundle grew to ~225 kB gzip** with the M2 screens → routes are lazy-loaded (209.7 kB) and

### Known limitations and caveats (honest list)

- **No production mail delivery.** Transports are `log` and `file` (development/test only, refused in
  production) and `disabled`. In production a "forgot password" request is accepted but no email is sent;
  administrators can set passwords and operators can use `nexora user reset-password`. SMTP arrives with the
  job queue in M3 (R-11).
- **Reset emails are sent in-process** after the response; a crash before delivery loses the message (R-11).
- **Expired sessions and reset tokens are not purged yet** (they are rejected, just kept). Rate-limit buckets
  are purged opportunistically. A scheduled cleanup job arrives with the job queue (M3).
- **Not implemented:** email verification, MFA/2FA, SSO/OAuth, API tokens for non-browser clients.
- **Content capabilities do not exist yet**, so Editor, Author, Contributor and Viewer can only sign in and
  manage their own profile until M3.
- **Setup token in the log** when `SETUP_TOKEN` is unset (R-09). Per-account lockout can be triggered by
  anyone who knows an address (R-10).
- **Fixed-window rate limits** allow up to twice the limit across a window boundary.
- **Idle-timeout precision**: session activity is written at most once a minute, so idle expiry is accurate
  to about 60 seconds.
- **The production-like Compose stack serves plain HTTP on 127.0.0.1** with Secure cookies. Browsers accept
  Secure cookies on `localhost`/`127.0.0.1`, so it works locally, but any real deployment must terminate TLS
  in front of it; otherwise sign-in cookies are rejected.
- Local tests ran against PostgreSQL 16; CI and Compose use 17.
- **GitHub CI:** run #9 (commit `d4dce53`) passed all six jobs: lint/format/typecheck/build/bundle budget, unit + integration + drift + E2E, Node 23.7.0 and 24 compatibility, dependency audit, container images.

## Milestone 3 — Content, media and background jobs

Plan, scope and decisions: [`docs/milestones/m3-content-media-jobs.md`](../milestones/m3-content-media-jobs.md).

### Starting point
M2 delivered identity, sessions, capability-based authorisation and the audit log. Mail was sent in-process with
development transports only, expired security records were never purged, and the content roles could only sign in.

### What was built
- **Job queue** (`apps/api/src/modules/jobs`): PostgreSQL table, transactional enqueue with `NOTIFY`, claims with
  `FOR UPDATE SKIP LOCKED`, exponential backoff, `dead` after the last attempt, reclaim of abandoned claims,
  ownership-checked completion, dedupe keys, recurring tasks that run once per slot, graceful shutdown that releases
  unfinished work, worker heartbeats. Embedded in the API (`JOBS_WORKER=embedded`) or standalone (`dist/worker.js`).
- **Mail**: SMTP transport (TLS and certificate checks required in production); password-reset emails are produced
  by a job that creates the token at send time, so job payloads never contain it.
- **Maintenance**: hourly purge of expired sessions, reset tokens, rate-limit buckets, finished jobs and stale worker
  heartbeats; scheduled publishing every minute; trash purge hourly.
- **Content model**: content types (Post, Page, custom) with custom fields (text, long text, number, yes/no, date,
  choice, URL, email, media); taxonomies (Category, Tag, custom) and terms; entries with draft/pending/scheduled/
  published states, a separate trash, hierarchical paths, slugs, excerpts, featured images, a structured rich-text
  body, optimistic concurrency, revisions with restore, bulk actions, search and filters.
- **Content capabilities** (`content.*`, `terms.manage`, `content_types.manage`, `media.*`, `jobs.manage`) mapped
  to the built-in roles by the migration, and one content policy for own vs. others' entries and live content.
- **Media**: content-sniffed uploads, re-encoding without metadata, WebP variants via a job, local and S3 drivers,
  `/uploads` serving with safe headers and byte ranges, usage counts, ownership rules.
- **Admin**: content lists, the editor (TipTap rich text, scheduling, slug, excerpt, featured image, terms, custom
  fields, parent page, revisions, unsaved-changes guard, conflict handling), media library and picker, term
  management, content type and field builder, background jobs page, command palette; navigation generated from the
  content model.
- **Infrastructure**: Compose `worker` service and shared `media-data` volume; nginx routes `/uploads` and allows
  large bodies on the upload endpoint only; CI runs an S3-compatible server for the S3 driver tests.

Issues found and fixed during M3 verification:

- **The storage drivers were never committed.** The project's `.gitignore` rule `storage/` (meant for local uploads)
  also matched `apps/api/src/modules/media/storage/`. Local checks passed because the files existed on disk; a
  fresh copy of the tracked files on Node 23.7 failed to compile, and CI runs #13 and #14 failed. The rules are now
  anchored and the files committed (`7e00906`).
- **A form submitted natively** (full page reload) in the content type dialog, after a lint-driven refactor dropped
  `preventDefault` while the matching JSX change silently failed to apply. Found by E2E; fixed.
- **"Load latest version" after a conflict reused the cached (stale) entry** instead of refetching. Found by E2E;
  it now fetches from the server.
- **Jobs page overflowed on phones** (an error message capped at 448 px). Found by E2E on the 375 px viewport.
- **Initial bundle exceeded its budget** (216.9 kB) because the navigation imported every content schema; the
  shared contracts and the content-model query were split (214.7 kB).
- **nodemailer 10.1.2 had three moderate advisories** (address parsing); upgraded to 10.1.7 (and the test-only
  smtp-server/mailparser to releases that use it).
- **Command palette acted on a stale result list**: Enter could open the first item of the previous list while the
  deferred filter caught up (seen on CI's slower mobile run). Static commands now filter on the live input.
- **The parent-page selector loaded only 20 entries** (it reused the list's page size); it now loads up to 100.
- **Flaky job-queue test** relying on rows inserted in the same millisecond keeping their order; made deterministic.
- **An upload failure path could delete a stored file after its row was committed** (flagged by lint
  `return-await`); restructured so cleanup only happens when the database write failed.

### Known limitations and caveats (honest list)

- **No public site yet.** Content can be created, scheduled and published, but nothing renders it for visitors
  until M4 (themes, site runtime, Delivery API). "View" links are therefore absent.
- **Pages use the rich-text editor**; the visual builder arrives in M5.
- **Admin search** is case-insensitive substring matching on title, excerpt and body text (no ranking, no full-text
  index); fine for small and medium sites.
- **Permissions are per capability, not per content type** (e.g. "authors may publish posts but not pages" is not
  expressible yet). Changing an entry's author is not supported.
- **Revisions** snapshot the content; there is no visual diff, and publishing an older revision while keeping a newer
  draft is not supported.
- **The parent-page selector lists at most 100 entries** of the type.
- **Uploads are buffered in memory** (R-18); GIF, PDF, audio and video are stored as uploaded (R-15); media is public
  by URL (R-17). Image variants are WebP only; no cropping or focal point.
- **The admin bundle is at 214.7 of 215 kB.** The next feature that touches the shell must make room (e.g. load
  more of the layout lazily) rather than raise the budget silently.
- **Jobs are at-least-once** (R-14). Recurring tasks depend on at least one worker running; the jobs page warns when
  none has reported for 90 seconds.
- **MinIO images are no longer published on Docker Hub**, so S3 tests use `adobe/s3mock`; real AWS S3 was not tested.
- Local tests ran against PostgreSQL 16; CI and Compose use 17.

Planned scope (to be confirmed at milestone start):

   caching headers and invalidation on publish.
